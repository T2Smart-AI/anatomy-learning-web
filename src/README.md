# src/ — application source

Clean-room, original code. See root `README.md` and `SPEC.md` for the
user-facing spec.

## Layout

- `app.js` — wiring: grouped browser (system→subgroup / region / A–Z),
  global search, keyboard navigation, resizable layout (splitter drags +
  focus/maximize mode, sizes persisted), viewer, detail, quiz, bookmarks,
  flashcards, theme switcher, EN/ES/FR/LA switcher, responsive layout.
- `anatomy-data.js` — `SYSTEMS` (12), `REGIONS` (8), `SUBGROUPS` (per
  system), `HISTOLOGY` (16), `STRUCTURES`
  (209: id, system, subgroup, region, en, la, es, histology, descriptions).
  Every id in `part-map.json` has a structure entry (no dead clicks).
- `viewer3d.js` — Three.js viewer: BodyParts3D 4.0 meshes (CC BY 4.0,
  `models/`, one `.bin.gz` per source system), merged per system,
  invisible per-part pickers (one per atlas part — every mesh area
  resolves to its card), on-demand highlight (a card may span several
  source systems; all are ensured), labels,
  isolate/x-ray/explode, orbit + manual clamped wheel zoom,
  screenshot-safe (`preserveDrawingBuffer: true`).
  **Living anatomy** (`setAnimate`): heart and lungs are extracted into
  their own centered meshes that pulse/breathe (transform-only, shared
  material), while arterial/venous/nervous/digestive materials get an
  `onBeforeCompile` emissive band that travels along object-space height
  (blood flow, nerve signals, peristalsis).
  **Progressive loading:** tier-1 systems (skeletal, muscular,
  integumentary, connective) load first; the rest stream in the
  background or on demand via `ensureScope(ourSystem)`.
- `quiz.js` — Find-Word / Find-Point engine, scoring, streak.
- `storage.js` — per-device persistence (localStorage, memory fallback).
- `themes/` — generated per-theme background textures (SVG), produced by
  `../tools/make-theme-assets.mjs` (deterministic — re-run to regenerate).
- `vendor/` — Three.js r160 + addons (MIT), resolved through the
  import map in `../index.html`.
- `models/` — `atlas.json` + `sys-*.bin.gz` (CC BY 4.0, see
  `ATTRIBUTION.md`) + `part-map.json` (our structure id → part indices).

## Data pipeline

`models/atlas.json` and `sys-*.bin.gz` are generated by
`../tools/repack-by-system.mjs` from the raw mixed BodyParts3D chunks.
Part indices are stable — `part-map.json` references them. Never
hand-edit `atlas.json`; edit the generator and re-run it.

`part-map.json` (every one of the 2,234 parts → a structure card) is
generated by `../tools/extend-part-map.mjs`: curated name rules first,
then distinctive-token name matching guarded by source system, then
nearest-neighbour by bounding-box center (same system within 15 cm,
else any system). It preserves the original map verbatim (shared parts
stay shared) and always runs against the committed map — `git checkout
-- src/part-map.json` before re-running. CI enforces 100% coverage
(`node tools/extend-part-map.mjs --check`) so no mesh area can become a
dead click again.
